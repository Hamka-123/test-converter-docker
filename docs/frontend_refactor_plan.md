### Контекст
- устаревший `static/js/script.js` содержит смешанную логику запросов, отображения, кеша и событий
- в `static/js/v2/` уже начата модульная архитектура:
  - `api.js` — API-запросы
  - `ui.js` — рендеринг
  - `storage.js` — локальный кеш
  - `main.js` — инициализация и связь модулей

### Цель
Привести фронтенд к чистой, поддерживаемой архитектуре с разделением ответственности:
- `index.html` — только структура и подключение модулей
- `js/v2/api.js` — только коммуникация с backend
- `js/v2/ui.js` — только построение DOM и отображение данных
- `js/v2/storage.js` — только работа с localStorage / кешем
- `js/v2/main.js` — только orchestration, инициализация и события

### Ожидаемый результат
- фронтенд `Python_HTTP_server/app/static` работает в едином модульном режиме
- `index.html` загружает только `v2/main.js`
- нет дублирования логики между `script.js` и `js/v2/*`
- UI отделён от API и кеша
- структура фронтенда понятна и легко расширяема

### Критерии приёмки
- `static/index.html` запускает модульный фронтенд
- `js/v2/api.js` используется для всех запросов к backend
- `js/v2/ui.js` отвечает за отрисовку результата
- `js/v2/storage.js` отвечает за localStorage
- `js/v2/main.js` делает только orchestration и event binding
- работа с `get-rates`, `do-conversion`, `get-conversion-logs` корректная

> Важно: задача не просто “починить”, а привести фронтенд к архитектуре с разделением на API / UI / storage / init.
