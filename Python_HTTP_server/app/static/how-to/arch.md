# 🏗 Текущая архитектура: Currency Converter MVP

## 1. Уровень инфраструктуры (Docker)
Приложение полностью изолировано в одном Docker-контейнере.
* **Persistent Storage (Volume):** Используется проброс папки (mount) из хост-системы в контейнер. Это критически важно: благодаря этому база данных `logs.db` не стирается при перезагрузке контейнера.
* **Networking:** Контейнер пробрасывает порт (8000/8001) наружу, позволяя браузеру взаимодействовать с Python-сервером.

## 2. Бэкенд (Python / "The Engine")
Сервер на базе стандартной библиотеки `http.server` выполняет роль «швейцарского ножа»:
* **Static Server:** Раздает фронтенд-файлы (HTML, CSS, JS) по запросу браузера.
* **API Gateway:** Принимает запросы на `/get-rates` и `/get-conversion-logs`.
* **External Integration:** Выступает прокси-клиентом для Frankfurter API, забирая актуальные курсы валют.
* **Business Logic:** Рассчитывает кросс-курсы (через EUR) и готовит данные для записи.
* **Persistence Layer:** Управляет базой данных через `sqlite3`. Внедрен механизм миграций (скрипт `migrate.py`) для управления схемой таблиц.

## 3. Фронтенд (JS + HTML + CSS / "The Client")
Клиентское приложение берет на себя значительную часть логики:
* **State Management:** В памяти JS хранится объект `currencyList` с актуальными коэффициентами.
* **Caching Layer (LocalStorage):** Приложение работает автономно, сохраняя слепок курсов в браузере для мгновенной загрузки.
* **UX Logic:** Реализован **Debounce** (задержка ввода) и двусторонний расчет (из любого поля).
* **Real-time Polling:** Имитация живых обновлений через регулярный опрос бэкенда каждые 5 минут.

## 4. Схема потоков данных (Data Flow)
1. **Загрузка:** Браузер → Docker → Python → Чтение `index.html` с диска.
2. **Инициализация:** JS в браузере → LocalStorage (есть данные?) → если нет → API `/get-rates`.
3. **Конвертация:** Ввод числа → JS (ожидание 500мс) → Запрос на сервер → Python (расчет и запись в SQLite) → Ответ клиенту.
4. **Логирование:** Кнопка "Show Logs" → Запрос на сервер → Python (чтение SQLite) → JSON → JS (рендер таблицы).

## 📊 Итоговая оценка (QA/DevOps View)

| Плюсы (Ready for Prod) | Риски (Technical Debt) |
| :--- | :--- |
| **Stateful:** Данные сохраняются во внешнем томе (Volume). | **Scaling:** SQLite ограничена при параллельной записи. |
| **UX:** Мгновенный старт благодаря кэшированию в LocalStorage. | **Sync:** Синхронный `http.server` блокирует поток на время запроса. |
| **Maintainability:** Наличие скриптов миграции схемы БД. | **Monolith:** Сбой сервера отключает и API, и раздачу статики. |
