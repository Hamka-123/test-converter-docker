# Архитектура проекта: Конвертер валют

В проекте реализована **слоистая архитектура (Layered Architecture)**, которая разделяет ответственность между компонентами, делая код чистым, тестируемым и легким в поддержке.



---

## 1. Слой представления (Web Server)
**Файл:** `web_server.py`  
**Роль:** Диспетчер и транспорт.

*   **Обязанности:** 
    *   Прием входящих HTTP-запросов (GET, POST).
    *   Парсинг JSON-данных из тела запроса.
    *   Маршрутизация (определение, какой сервис вызвать на основе пути `self.path`).
    *   Отправка ответов пользователю через универсальный метод `_send_response`.
    *   Раздача статических файлов (HTML, CSS, JS).
*   **Ограничение:** Не содержит бизнес-логики и не знает о структуре базы данных.

---

## 2. Слой бизнес-логики (Services)
**Файл:** `services.py`  
**Роль:** "Мозговой центр" приложения.

*   **Обязанности:** 
    *   Выполнение математических расчетов (формулы конвертации, округление).
    *   Валидация данных (проверка корректности входных параметров).
    *   Взаимодействие с внешними API (например, получение курсов валют).
    *   Форматирование данных для фронтенда (например, перевод даты в `isoformat`).
*   **Ограничение:** Не знает о существовании HTTP-протокола. Работает только с Python-объектами (dict, list, float).

---

## 3. Слой доступа к данным (Repository)
**Файл:** `repo.py`  
**Роль:** Хранилище и кладовщик.

*   **Обязанности:** 
    *   Выполнение прямых SQL-запросов к базе данных (SQLite/MariaDB).
    *   Сохранение логов конвертации и получение истории.
    *   Абстрагирование сложности работы с БД от остального приложения.
*   **Ограничение:** Не принимает решений о том, *что именно* считать или сохранять. Только исполняет команды записи/чтения.

---

## 4. Инфраструктура и Зависимости
**Файлы:** `start_server.py`, `dependencies.py`  
**Роль:** Сборка и запуск.

*   **Обязанности:** 
    *   Инициализация объектов (создание экземпляра `repo`).
    *   Настройка логирования.
    *   Запуск бесконечного цикла `HTTPServer`.

---

## Преимущества такой структуры

| Ситуация | Решение |
| :--- | :--- |
| **Смена БД** | Достаточно переписать только `repo.py`. |
| **Новый интерфейс (Бот)** | Создается новый файл-обработчик, который вызывает те же функции из `services.py`. |
| **Ошибка в расчетах** | Исправляется в одном месте — в `services.py`. |
| **Изменение дизайна** | Редактируются только файлы в папке `static/`. |

## Структура файлов проекта
```text
project/
├── static/                # Фронтенд (HTML, CSS, JS)
├── data/                  # Локальные данные (JSON файлы)
├── web_server.py          # HTTP логика и маршрутизация
├── services.py            # Математика и бизнес-логика
├── repo.py                # Работа с базой данных
├── dependencies.py        # Инициализация и зависимости
└── start_server.py        # Точка входа в приложение
